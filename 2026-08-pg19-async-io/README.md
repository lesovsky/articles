# Асинхронный I/O в PostgreSQL: материалы эксперимента

Полный набор данных к статье [`pg19-async-io.md`](pg19-async-io.md).

Вопрос эксперимента: что даёт асинхронный ввод-вывод, появившийся в PostgreSQL 18
и доработанный в 19, — по умолчанию, после настройки и в тех местах, где он не
даёт ничего.

## Стенд

| | |
|---|---|
| Гипервизор | KVM/Proxmox |
| CPU / RAM | 8 vCPU (Xeon Gold 5220R @ 2.20GHz), 4 GB |
| Диск | raw, `cache=none`, `aio=native`, iothread, SSD emulation, VirtIO SCSI single |
| ФС и ядро | ext4, Debian 13, ядро 6.12, планировщик `none`, `read_ahead_kb = 128` |
| PostgreSQL | 19beta2, снапшот `19~beta2-1~20260807.2015.g7673dfe771e.pgdg13+1`, собран с liburing |

Кеш гипервизора отсутствует — проверено чтениями с `O_DIRECT` по диапазонам
128 MB, 1 GB и 8 GB: латентность одинаковая, значит выше гостя ничего не кешируется.

Фиксированный конфиг PostgreSQL во всех прогонах — `scripts/00-setup.sh`:
`shared_buffers = 512MB`, `max_parallel_workers_per_gather = 0`, `autovacuum = off`,
`track_io_timing = on`, `io_max_concurrency = 64` (вычислен автоматически, это
документированный максимум). На уровне ОС — `vm.swappiness = 1`.

## Как повторить

Скрипты рассчитаны на каталог `/bench/scripts/` и запускаются по порядку.
Между каждой итерацией любого прогона сервер останавливается, сбрасывается
page cache и сервер запускается снова — иначе 512 MB `shared_buffers` переносят
состояние между итерациями.

| Скрипт | Что делает |
|---|---|
| `00-setup.sh` | базовый конфиг кластера |
| `01-dataset.sh` | генерация таблицы и индекса |
| `02-wait-sampler.sh` | сэмплер событий ожидания, 100 опросов/с |
| `03-runner.sh` | одна ячейка: применить настройки, N раз повторить холодный прогон |
| `04-exp1.sh` | эксперимент 1 — три метода × три нагрузки |
| `05-exp2.sh` | эксперимент 2 — пул воркеров, развёртка 1→16 сессий |
| `06-exp3.sh` | эксперимент 3 — развёртки `effective_io_concurrency` и `io_combine_limit` |
| `07-exp4.sh` | эксперимент 4 — наблюдаемость |
| `08-analyze.sh` | сводка по ячейкам |
| `09-charts.py` | графики (нужен matplotlib) |
| `10-exp5-session3.sh` | эксперимент 5 — головная таблица одной серией; эксперимент 6 — прогретый кеш; перемер fio |
| `11-exp5b.sh` | эксперимент 5b — истинный QD1 в той же серии |
| `12-strace.sh` | подсчёт системных вызовов бэкенда по методам |

## Данные

- `data/results.csv` — все 596 прогонов. Колонка `exp` разделяет эксперименты;
  цифры статьи берутся из `exp = 5` (головная таблица), `exp = 2` (пул),
  `exp = 3` (развёртки) и `exp = 6` (прогретый кеш).
- `data/summary.csv` — агрегаты по ячейкам.
- `data/waits.csv` — распределение событий ожидания.
- `data/observ/` — `EXPLAIN (ANALYZE, BUFFERS, IO)`, выборки `pg_aios`, `pg_stat_io`,
  сырые JSON от fio, вывод `strace` и лог отказа старта с параметром `io_workers`.

## Две оговорки

Числа сняты на бете, к релизу они могут измениться.

Выигрыш асинхронного чтения пропорционален латентности хранилища. У этого стенда
одиночное случайное чтение стоит 0.206 мс — это уровень сетевого диска, и на
локальном NVMe эффект будет заметно меньше. На быстром хранилище я не мерил.
